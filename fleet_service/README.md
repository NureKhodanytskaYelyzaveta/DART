# fleet_service

Консольна програма мовою Dart для обліку технічного обслуговування автопарку (варіант 15).

Програма розбирає вхідні записи, перевіряє їх, відбирає та групує дані, виконує сортування й формує звіт. Для зберігання одного запису використовується `ServiceRecord` (Dart record), класи в лабораторній роботі не застосовуються.

## Запуск і перевірка

```bash
dart pub get
dart run bin/fleet_service.dart
dart analyze
dart format .
```

## Структура проєкту

- `bin/fleet_service.dart` — запуск програми та виведення результатів.
- `lib/fleet_service.dart` — функції розбору, перевірки й обробки записів.
- `lib/service_data.dart` — вхідний список із 24 рядків, зокрема пошкоджених.
- `docs/` — збережені результати аналізу та запуску.

## Основні рішення

- `parseLine()` перевіряє кількість полів і перетворює значення. Для чисел використано `int.tryParse` і `double.tryParse`, щоб некоректні дані не спричиняли аварійного завершення.
- `parseIsoDate()` перевіряє формат і відповідність складових дати, щоб відхиляти неіснуючі дати.
- `validateRecord()` окремо перевіряє номер автомобіля, пробіг, вартість і дату обслуговування.
- Для обробки колекцій використовуються `where`, `map` і `fold`. Групування виконується за типом робіт.
- `buildReport()` формує звіт за допомогою `StringBuffer`.
- `makeCounter()` і `costAtLeast()` демонструють використання замикань.
- Регулярні вирази застосовуються для перевірки та маскування номерів. `maskPlate()` використовує `replaceAllMapped` та іменовані групи.
- Для обчислення кількості днів після обслуговування використовується `DateTime.difference()`.

Параметр `now` у функціях перевірки та обчислення дат дає змогу передати фіксовану дату під час тестування. Якщо її не передано, використовується `DateTime.now()`.

## Додаткові відомості

Оператор розіменування `!`, `late` і тип `dynamic` у проєкті не використовуються. Для обробки nullable-значень застосовано перевірки, `??`, `?.` і промоцію типів.

Сторонніх залежностей часу виконання немає. Пакет `lints` використовується для статичного аналізу коду.
